Release engineering froze the Ember pipeline because antlock, the Go gatekeeper deciding whether an Apache Ant build may ship, approves tampered builds and blocks clean ones. Repair only forgegraph, propseal, evidenceledger, and reportwire. The command package, audit model, Makefile, module file, and ember_workcell stay immutable. The workcell is valid; grading invents fresh projects, so hardcoded answers cannot ship.

The gate must honor ember_integrity_contract.json including violation_codes, detail_rules, co_fire_examples, sha256_pattern, and package.minimum_unique_operating_systems. Digests must be exactly sixty-four lowercase hex characters; uppercase hex is INVALID_SHA256. Evidence needs two distinct operating_system values or INSUFFICIENT_PLATFORMS. Every applicable violation must appear independently, including digest and content checks after DUPLICATE_ARTIFACT or DUPLICATE_PLATFORM. INVALID_SHA256 detail must be literal artifact, sidecar, archive, or package entry path. Unequal sha256 and sidecar_sha256 strings must yield CHECKSUM_MISMATCH even when INVALID_SHA256 applies. Dependencies must be unique and ascending. TARGET_CYCLE covers every oversized SCC member and every self dependency. Property cycles mark every stack name while PROPERTY_MISMATCH still carries the required value.

Successful verification writes build/ember_gate_decision.json with project, verdict, targets, properties, and violations. Targets and properties sort by name, violations by code then subject then detail, dependencies ascending, compact JSON, and one trailing newline. Verdict is RELEASABLE when violations are empty and otherwise BLOCKED.
